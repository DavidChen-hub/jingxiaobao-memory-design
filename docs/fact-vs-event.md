# 事实 vs 经历：判定标准

> 这是 `docs/design.md` §3.5 的独立版，方便在写卡、审候选、做数据迁移时直接引用。

## 一句话判据

**把日期拿掉还成立的是事实（fact）；拿掉日期就说不清的是经历（event）。**

## 两类各是什么

- **事实 fact**：关于人的稳定信息——称呼/名字、喜好/讨厌、身份、住处、工作学校、约定、规矩、禁忌、关系定位。
- **经历 event**：发生过的事——当时聊了什么、她做了什么、学到什么教训、情绪转折、没聊完的话题；必须带时间。

## 行为差异

| | 事实 fact | 经历 event |
|---|---|---|
| 进哪 | 事实卡（≤1200 字，8 轮重建） | 最近经历（24h，本场合 4 + 别处 2 条） |
| 时间 | 不带日期 | 必须带日期 |
| 寿命 | 不衰减；变了用 `invalidAt` 取代 | 30 天半衰期，180 天清 |
| 写入 | 候选池，3 次/14 天转正 | 直接入库 |
| 写错的代价 | **永久污染每一轮** | 会慢慢淡出 |

## 例子

- **事实**：主人不吃香菜；主人要求群里别讲隐私；阿青每周组织桌游局；她自己的名字/昵称。
- **经历**：阿青今晚赢了桌游；主人今天说去洗澡；她今天在群里说了某句；她修 bug 修了两轮没修成。
- **边界**：「她学到：改代码前先同步运行副本」是经历；如果把它定为规矩，再补一条事实「规矩：改代码前先同步运行副本」。

## 三个容易混的点

1. **混合句拆两条**：如「主人说以后回评论前先想语气」——约定本身是事实（「约定：回评论前先想语气」），当时说是经历；只留一条时留事实。
2. **变了不要并列**：新事实写进去，旧事实标 `invalidAt`，不要两条都当现行事实。
3. **拿不准就记经历**（importance 0.4）：事实写错会永久污染每一轮；经历写错会随半衰期淡出。

## 实现提醒

`remember` 的 `kind` 目前是选填，不传会按 `fact` 落库；审候选时按上面的判据人工兜底。
