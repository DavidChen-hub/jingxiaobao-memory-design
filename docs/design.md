# 大肥鱼长期记忆系统：设计与开源说明

> 版本：2026-11-16（期一、期二已上线；期三的潮汐/路由/图谱/星图已完成）
> 适用：本仓库 `jingxiaobao-memory-design` 的 `src/features/memory.js` 及其子模块。
> 本文两个用途：① 记忆项目的设计与取舍说明；② 视频/开源参考底稿。
>
> 本仓库从 Aurabot 1.1.6 的本地分叉抽取；上游 `aureth-labs/dsh-aurabot-qq`（MIT，1.2.1）是另一套记忆实现，**不保证兼容**。本仓库只含记忆核心，不含 QQ/抖音/评论/文章/人格/人物图。

---

## 0. 一句话

**一个跑在本地的、按「场合」隔离的、事实与经历分开注入的长期记忆系统**：让住在 QQ/抖音里的 AI 伙伴能记住人、记得事、换场合不串味，又不至于每轮把整个记忆库塞进上下文烧钱。

---

## 1. 为什么做（普通记忆库的痛点）

市面上的「AI 记忆」大多长这样：把对话切块 → 向量化 → 存库 → 每轮检索 top-k 拼进 prompt。用在聊天机器人上会踩五个坑：

| 痛点 | 具体表现 |
|---|---|
| **压缩即失忆** | DSH 会话满了会自动压缩，只剩摘要。她「一觉醒来只记得大概」，昨天说好的事今天就糊了 |
| **跨场合串味** | 主人在私聊里说的话，被群聊检索到并当着所有人的面说出来——隐私事故 |
| **事实和经历混在一个桶** | 「主人不吃香菜」（事实）和「昨天下午她回了某个群友一句」（事件）混在一起，既有日期又不该有日期，检索互相干扰 |
| **检索只看关键词** | 问「上次那个」时 BM25 抓不到，因为字面不重合 |
| **成本不可控** | 记忆几千条后，每轮检索+注入的体积越来越大，token 账单跟着长 |

这套系统就是逐条对着这些坑改的。

## 2. 它是什么（架构总览）

```
写入侧                          存储（本地 JSON，零外部依赖）
聊天流水 ──(每天两次整理)──▶ 事实 / 事件 / 候选池
她主动 remember ──────────▶ 事实
各模块（抖音/B站/日记/翻唱）──▶ 事件（带 scope）
她每轮说出口的话 ─────────▶ 经历流（source=turn，带 board）
                                      │
注入侧（每轮，按板块挑）               ▼
┌──────────────────────────────────────────────┐
│ ① 事实卡（长期，≤1500 字，每 8 轮重建一次）      │
│ ② 最近经历（24 小时，本场合 4 条 + 别处 2 条）   │
│ ③ 最近原话（≤2400 字，防压缩失忆）              │
│ ④ 命中记忆（本地 BM25，最多 3 条）               │
└──────────────────────────────────────────────┘
```

五块记忆（`scope`）：

- `owner` 主人私聊
- `group:<群号>` 某个群（另有 `group` 跨群公共）
- `douyin` 抖音公开活动
- `friend:<QQ 或名字>` 她自己的朋友
- `self` 她自己的经历 / 空间日记
- 另有 `quarantine`（导入旧档案先隔离，不注入）、`public:bili`（B 站公开活动单独一桶）、`global`（人工审核过的公共知识）

**fail-closed 原则**：缺 scope、板块算不出来、空 board —— 一律不可见，宁可不给。

## 3. 期一：注入层重构（v2，2026-11-08 上线）

### 3.1 事实卡投影（借鉴 Ido1um/DeepSeek-memory-Ido1um、dsh-hippocampus）
把事实库压成一张 ≤1500 字的卡，**每 8 轮重建一次**，中间轮次复用缓存。

- 只吃「事实」，不吃「事件」和「日记」——事实不需要时间戳
- 按人分组（主人 / 每个朋友 / 每个群成员），槽位有上限（称呼、生日、学校、喜好、约定…）
- 超预算时按 importance 用「补充：」行兜底填充
- 旧事单独一行「旧事：…」，不混进当前事实

**为什么每 8 轮才重建**：卡区稳定 = prompt 前缀稳定 = 命中缓存（0.02 元/百万 vs 未命中 1 元/百万）。缓存就是这套系统最大的省钱手段。

### 3.2 最近原话（防压缩失忆）
不依赖 DSH 的压缩事件（实测监听不到压缩），改成**每轮带最近若干轮原话**（≤2400 字）。压缩之后她仍能看见刚才聊了什么。

### 3.3 事件层（`memory/events.js`）
事件单独成段，**带日期**、24 小时窗口、本场合优先：

```
【最近经历】
- [11-15 15:11] 在群里说：你说的哪张 我这边没看到图 再发一次我看看
- [11-15 14:10] 在群里说：你叫我我基本都在吧 除非我睡着 那真没办法
```

### 3.4 候选池（宽进严出，借鉴 Ido1um 的 pass/mark/block）
模型抽出来的低置信内容先进候选池，不直接进记忆库：

- 同一 key 被提到 **3 次** → 转正
- **14 天**没转正 → `blocked`（不再算 pending）
- blocked 后再 **30 天** → 从池子里清掉（只留计数）
- 转正时保留原 scope，跨板块的改写一律丢弃

### 3.5 事实和经历怎么分（写卡 / 审候选时用）

**一句话判据：把日期拿掉还成立的是事实（fact）；拿掉日期就说不清的是经历（event）。**

- **事实 fact**：关于人的稳定信息——称呼/名字、喜好/讨厌、身份、住处、工作学校、约定、规矩、禁忌、关系定位。
- **经历 event**：发生过的事——当时聊了什么、她做了什么、学到什么教训、情绪转折、没聊完的话题；必须带时间。
- **拿不准就记经历**（importance 0.4）：事实写错会永久污染每一轮；经历写错会随半衰期淡出。
- **混合句拆两条**：如「主人说以后回评论前先想语气」——约定是事实（「约定：回评论前先想语气」），当时说是经历；只留一条时留事实。
- **变了不要并列**：新事实写进去，旧事实标 `invalidAt`，不要两条都当现行事实。

| | 事实 fact | 经历 event |
|---|---|---|
| 进哪 | 事实卡（≤1200 字，8 轮重建） | 最近经历（24h，本场合 4 + 别处 2 条） |
| 时间 | 不带日期 | 必须带日期 |
| 寿命 | 不衰减；变了用 `invalidAt` 取代 | 30 天半衰期，180 天清 |
| 写入 | 候选池，3 次/14 天转正 | 直接入库 |
| 写错的代价 | 永久污染每一轮 | 会慢慢淡出 |

**例子**

- 事实：主人不吃香菜；主人要求群里别讲隐私；阿青每周组织桌游局；她自己的名字/昵称。
- 经历：阿青今晚赢了桌游；主人今天说去洗澡；她今天在群里说了某句；她修 bug 修了两轮没修成。
- 边界：「她学到：改代码前先同步运行副本」是经历；如果把它定为规矩，再补一条事实「规矩：改代码前先同步运行副本」。

> 实现注意：`remember` 的 `kind` 目前是选填，不传会按 `fact` 落库（T-043 待修）；审候选时按上面的判据人工兜底。

## 4. 期二：五板块隔离（T-026，2026-11-13 上线）

### 4.1 scope 推导与显式写入
- `scopeOfChat(chat)`：私聊→owner（非主人→friend:QQ）、群→group:<群号>、system→douyin
- 写入口**显式传 scope**：抖音 4 处（分享/评论@主人/回复评论/私信回主人→owner）、B 站 8 处（→public:bili）、画图、翻唱、日记
- 从聊天流水整理时按 `chatId/about/aboutName` 推导，拿不准就进 `quarantine`

### 4.2 检索/注入前先按板块过滤
`search()` 在**打分之前**过滤（不是取完 top-k 再筛），否则别的板块的高分结果会占满名额。

### 4.3 人物档案按板块存
键从 `profiles[QQ]` 改成 **`profiles[scope|QQ]`**：
- 群里的档案只用群里的记忆写，不会带出私聊的私事
- 面板显示板块标签（「主人私聊」「群 123456」）
- 旧纯 QQ 键读时兜底、整理时自动迁移、canonical 键永远优先

### 4.4 她自己的经历也按场合收窄
`source:'turn'` 的经历带 `board`：**本场合 + 主人私聊** 可见。群里的她能在私聊被想起，私聊里听到的话不会跑到群里。

### 4.5 抖音轻量注入
抖音 system 会话单独接线，只给「抖音 + 朋友 + 自己」的轻量版（卡 500 字、经历 4 条/400 字），不带主人私事和群。

## 5. 期三：进行中（潮汐已完成）

| 顺序 | 内容 | 解决什么 | 状态 |
|---|---|---|---|
| 1 | **潮汐式衰减** ✅：事件按半衰期淡出，事实永不过期 | 现在是一套遗忘曲线管所有，事件活太久、事实被误伤 | 2026-11-16 完成（T-034） |
| 2 | **问法路由** ✅：问句→主体/槽位/主题/日期，槽位>主体>主题>词法，facet 门控 | 「上次那个」类问题 BM25 抓不到 | 2026-11-16 完成（T-039） |
| 3 | **记忆图谱** ✅：时序/同一个人/同一主题/因果边，召回 1 跳 | 顺着一条线找回一串相关的事 | 2026-11-16 完成（T-040） |
| 4 | **星图可视化** ✅：只读 Canvas 页面 + `/memory/graph` | 人能看见「她记得什么」 | 2026-11-16 最小版（T-041） |

**潮汐口径（T-034）**：
- 事实：`retention = 1`，不随时间衰减，也不会被自动清理；只有被新事实取代（`invalidAt`）才在半年后回收。
- 事件：`retention = 0.5 ^ (距上次发生/被想起的天数 / 30)`；默认 30 天半衰期，60 天剩 1/4，180 天剩 1/64。
- 证据分 `s/(s+2)`（s = 被想起次数）只做轻微排序加权（最多 +10%），不设硬门槛。
- 事件清理：`importance >= 0.6` 的留着；其余默认 180 天（6 个半衰期）没再被想起才清。
- **不做情绪加权半衰期**（产品上明确不做「生一次气记半年」这种）。

**问法路由（T-039）**：问句 → 主体/槽位/主题/日期；权重 槽位 120 > 主体 100 > 主题 60 > 日期 40；按问句 facet 门控；「你」指她、「你主人」指主人；零词法只救槽位/日期/点名的人。

**记忆图谱（T-040）**：时序（同聊天 2h）/同一个人（30d）/同一主题（7d）/因果（因为/所以/于是/难怪，2h）；同一对只留最强一条边；召回 1 跳补 1–2 条，只读投影、可重建。

**星图（T-041）**：`/aurabot/api/memory/starmap` 只读 Canvas 页面；`/memory/graph?board=` 给数据；最多画 400 节点；不加写接口。

**明确不做**：情绪加权半衰期（「生一次气记半年」）——主人否掉了。

## 6. 跟普通记忆库比，优势在哪

| 维度 | 常见做法（向量库 + top-k） | 这套系统 |
|---|---|---|
| 场合 | 不分，全局一个池 | 五板块 + fail-closed，跨场合默认不可见 |
| 注入 | 每轮检索 top-k | 卡（长期）+ 24h 经历 + 最近原话 + 命中，四段各司其职 |
| 事实/事件 | 混存 | 分开存、分开注入；事件带日期、事实不带 |
| 成本 | 随库增长线性上升 | 卡固定 ≤1500 字，前缀稳定吃缓存，实测每轮 ~2.9k 字符 |
| 依赖 | 向量库/嵌入模型/云服务 | 本地 JSON + 纯 BM25，零外部依赖，断网可用 |
| 遗忘 | 无或简单 TTL | 事实永不衰减；事件按 30 天半衰期淡出；过时留半年；硬上限 |
| 可控 | 黑盒 | 面板可看每条、可手改、可恢复；候选池可审计 |

## 7. 十个「小巧思」（常规之外的部分）

1. **主人格位强制 ownerName**：曾出现过 QQ 昵称覆盖、同一个人在卡里拆成两组的问题。现在主人永远显示配置里的称呼，不被昵称污染。
2. **档案按「板块+人」而不是「人」**：同一个人在不同群里有两份档案，互不串。
3. **去重只在同一板块内做**：同一句话在群里和私聊是两条，不互相覆盖。
4. **过时不是删除**：`invalidAt` + `supersededBy`，旧的留半年、可恢复、面板看得见。
5. **经历流同轮只记一条**：带工具调用的中间步骤（「让我看看」）有 `phase:'mid'`，不算正式回复。
6. **经历流隐私闸**：号码/邮箱/链接/无协议域名、成段引用对方原话、复述用户原话 → 一律不写进她的经历（经历是全局可见的）。
7. **经历有硬上限**：每 chat 4 条/小时、全局 80 条/天、总 800 条，防「她的话」把记忆库顶满。
8. **面板板块下拉走全量统计**：`/memory/scopes` 从整个库统计出现过的群/朋友，不受「最近 300 条」限制。
9. **影子日志两种模式都写**：切了正式注入后仍留一份「这一轮她实际拿到了什么」的快照，日报和排查都靠它。
10. **日报写硬判据**：卡字数、影子行数、候选池、板块串味、全量测试 —— 命中才说话，不靠感觉。
11. **按板块建 BM25 索引并缓存**：连 IDF/平均长度都只算本板块，私聊记录不会悄悄改变群里的相关度。
12. **迁移不整库重写**：读时补 scope、读时迁 B 站旧记录，下一次正常保存落盘，避免「运行中替换文件」丢更新。

## 9. 开源说明（发布时用）

**代码位置（本仓库）**
```
src/features/memory.js          主逻辑（存储/检索/注入/整理/候选池）
src/features/memory/card.js     事实卡投影
src/features/memory/events.js   事件层（24h、本场合优先）
src/features/memory/recent.js   最近原话
src/features/memory/route.js    问法路由
src/features/memory/graph.js    记忆图谱
src/features/memory/identity.js 身份卡
src/core/store.js               JSON 存储适配
src/core/llm.js                 LLM 接口适配（只依赖宿主 llm.stream）
src/core/config.js              最小配置归一化
test/memory*.test.js            130 个用例
examples/demo.mjs               假数据演示
```
> 面板、模块路由、星图 UI 不在本仓库；它们属于上游插件，本仓库只保留可独立运行的核心。

**数据文件（默认）**
```
$MEMORY_DATA_DIR/memories.json        记忆库（items + profiles + candidates + insights）
$MEMORY_DATA_DIR/memory-shadow.jsonl  每轮注入快照（排查/日报用）
$MEMORY_DATA_DIR/memory-daily.md      每天 22:30 的日报（可选）
```
> 不提交任何真实数据；测试与 demo 都写在临时目录。

**关键配置**（传给 `normalize()` 的 `memory` 段）
```jsonc
{
  "enabled": true,
  "v2": { "enabled": true, "shadow": false, "cardMaxChars": 1500, "recentMaxChars": 2400 },
  "decay": { "eventHalfLifeDays": 30, "eventForgetDays": 180 },
  "consolidateTimes": ["13:00", "22:00"]
}
```

**跑测试**
```powershell
node --test --test-concurrency=1 "test/*.test.js"
# 装了 npm 也可以用 npm test
```
> 必须串行（`--test-concurrency=1`），并行会有假失败。

**边界与已知限制**
- 数据是本机 JSON，不适合多写并发（同一进程内是同步读写，跨进程没有锁）
- 检索用 BM25（中文二元组），不是向量；语义近义靠「问法路由」补
- 旧档案迁移是「读时迁移」，只在下一次保存时落盘
- 情绪加权衰减明确不做

**许可**：代码 MIT；本仓库不含人物形象/素材（dsh-pet 的 webm 不在内）。如果以后加星图 UI，需随 Three.js 一起保留 MIT 版权头。

**来源**：从 `aureth-labs/dsh-aurabot-qq` 1.1.6 的本地分叉抽取；上游 1.2.1 是另一套实现，不保证兼容。详见仓库根目录 `THIRD-PARTY-NOTICES.md` 与 `README.md`。

## 10. 视频脚本（参考抖音「聊天窗」形式，不是 PPT）

**形式**（2026-11-17 00:49 主人更正，2026-11-20 再补画幅，以此为准）：**横屏 16:9**（成片 1920×1080，样片 1280×720），大肥鱼（桌宠形象）在画面里讲，**头顶冒气泡**，气泡文字随她说的话逐字出现；说到「记忆」「数据」时旁边浮出小卡片、数字滚动、板块色块。不是聊天窗 UI。动画需要外部生图/生视频模型与剪辑软件配合（分工见 T-033）。嘴型不重要，气泡 + 动作 + 声音就够。

**分镜（约 90–120 秒）**

| # | 画面 | 她说什么（示意） |
|---|---|---|
| 1 | 桌宠出场，头顶气泡 | 「我记性不太好，但我在改。」 |
| 2 | 一张卡从旁边滑入，标题「长期事实」 | 「我把关于你的事压成一张卡，每轮都带着。」 |
